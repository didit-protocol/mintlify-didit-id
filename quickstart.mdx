Issue a demo `EmployeeBadge` SD-JWT VC from the API, claim it in the hosted wallet, and verify a selective-disclosure presentation with Didit ID.

This quickstart uses the sandbox API at `https://idv0.staging.didit.me/v1`. Management endpoints use `Authorization: Bearer $DIDIT_API_KEY`. Holder and verifier protocol endpoints are public.

<Note>
  The examples use `curl` and `jq`. Set `DIDIT_API_KEY` to a tenant API key from the Didit Console.
</Note>

```bash cURL
export DIDIT_API_BASE="https://idv0.staging.didit.me/v1"
export DIDIT_API_KEY="<tenant-api-key>"

curl -sS "$DIDIT_API_BASE/credential-schemas" \
```

```python Python
import os
import requests

api_base = os.environ.get("DIDIT_API_BASE", "https://idv0.staging.didit.me/v1")
api_key = os.environ["DIDIT_API_KEY"]
auth = {"Authorization": f"Bearer {api_key}"}

response = requests.get(f"{api_base}/credential-schemas", headers=auth)
print(response.json())
```

  </Step>

  <Step title="Create a credential schema and template">
    Create a schema for an `EmployeeBadge` credential. Then create a template that uses that schema and sets a one-hour credential lifetime.

<CodeGroup>
```bash cURL
SCHEMA_ID="$(
  curl -sS -X POST "$DIDIT_API_BASE/credential-schemas" \
    -H "Authorization: Bearer $DIDIT_API_KEY" \
    -H "Content-Type: application/json" \
    --data '{
      "name": "Employee Badge",
      "vct": "EmployeeBadge",
      "attributes": [
        {
          "name": "employee_id",
          "type": "string",
          "sd": true
        },
        {
          "name": "role",
          "type": "string",
          "sd": true
        },
        {
          "name": "department",
          "type": "string",
          "sd": true
        }
      ]
    }' | jq -r '.uuid'
)"

TEMPLATE_ID="$(
  jq -n --arg schema "$SCHEMA_ID" '{
    schema: $schema,
    name: "std",
    validity_seconds: 3600
  }' |
  curl -sS -X POST "$DIDIT_API_BASE/credential-templates" \
    -H "Authorization: Bearer $DIDIT_API_KEY" \
    -H "Content-Type: application/json" \
    --data @- | jq -r '.uuid'
)"

echo "SCHEMA_ID=$SCHEMA_ID"
echo "TEMPLATE_ID=$TEMPLATE_ID"
```

```python Python
schema = requests.post(
    f"{api_base}/credential-schemas",
    headers=auth,
    json={
        "name": "Employee Badge",
        "vct": "EmployeeBadge",
        "attributes": [
            {"name": "employee_id", "type": "string", "sd": True},
            {"name": "role", "type": "string", "sd": True},
            {"name": "department", "type": "string", "sd": True},
        ],
    },
).json()
schema_id = schema["uuid"]

template = requests.post(
    f"{api_base}/credential-templates",
    headers=auth,
    json={"schema": schema_id, "name": "std", "validity_seconds": 3600},
).json()
template_id = template["uuid"]

print("SCHEMA_ID", schema_id)
print("TEMPLATE_ID", template_id)
```
</CodeGroup>

    `SCHEMA_ID` identifies the credential type and selectively disclosable claims. `TEMPLATE_ID` is the issuer-side configuration you use when you create an offer.
  </Step>

  <Step title="Create a credential offer">
    Create an OpenID4VCI credential offer from the template. The response includes the `offer_id`, the `credential_offer_uri`, the `pre_authorized_code`, the 6-digit `tx_code`, and a `claim_url` that opens the offer in the hosted wallet. Offers created this way expire after 10 minutes.

<CodeGroup>
```bash cURL
OFFER="$(
  jq -n --arg template_id "$TEMPLATE_ID" '{
    template_id: $template_id,
    claims: {
      employee_id: "E-1042",
      role: "Engineer",
      department: "Platform"
    }
  }' |
  curl -sS -X POST "$DIDIT_API_BASE/credential-offers" \
    -H "Authorization: Bearer $DIDIT_API_KEY" \
    -H "Content-Type: application/json" \
    --data @-
)"

OFFER_ID="$(echo "$OFFER" | jq -r '.offer_id')"

echo "$OFFER" | jq '{
  offer_id,
  credential_offer_uri,
  credential_issuer,
  pre_authorized_code,
  tx_code,
  claim_url
}'
```

```python Python
offer = requests.post(
    f"{api_base}/credential-offers",
    headers=auth,
    json={
        "template_id": template_id,
        "claims": {
            "employee_id": "E-1042",
            "role": "Engineer",
            "department": "Platform",
        },
    },
).json()
offer_id = offer["offer_id"]

print({k: offer[k] for k in (
    "offer_id", "credential_offer_uri", "credential_issuer",
    "pre_authorized_code", "tx_code", "claim_url",
)})
```
</CodeGroup>

    See the [credential offer API reference](/api-reference/openid4vci/credential-offers-post) for the full response shape.
  </Step>

  <Step title="Claim the offer in the hosted wallet">
    Open the `claim_url` from the offer response in a browser. The hosted wallet at [wallet-idv0.staging.didit.me](https://wallet-idv0.staging.didit.me) previews the offer, asks you to sign in with a passkey, and prompts for the `tx_code`. When you approve, the wallet runs the OpenID4VCI exchange itself: it redeems the `pre_authorized_code` and `tx_code` at `POST /oauth/token`, fetches a `c_nonce` from `POST /nonce`, and calls `POST /credential` with a holder proof JWT. Then it stores the SD-JWT VC.

<CodeGroup>
```bash cURL
echo "$OFFER" | jq -r '.claim_url'
# open the printed URL in a browser, sign in, enter the tx_code from the offer response, and claim
```

```python Python
print("Open this URL in a browser and enter the tx_code:", offer["claim_url"])
print("tx_code:", offer["tx_code"])
input("Press Enter once the wallet shows the credential... ")
```
</CodeGroup>

    <Frame caption="Add to Wallet: the issuer, the credential type, and each claim marked You choose (selectively disclosable) or Always shared. The transaction code entry and the Add to Wallet button follow below."><img src="/images/screenshots/wallet-claim-offer.png" alt="Wallet Add to Wallet screen showing an employee badge offer from skyhop-airlines with Given Name, Family Name, Employee Id and Department marked You choose and Tier marked Always shared" /></Frame>

    Your own wallet follows the same protocol. See [OpenID4VCI issuance](/guides/issuance) for the token, nonce, and credential calls.
  </Step>

  <Step title="Request a presentation">
    Create an OpenID4VP presentation request for the `role` claim. The response carries the `uuid` you hand to the wallet plus the `nonce` and the DCQL query Didit ID built for it.

<CodeGroup>
```bash cURL
PRESENTATION="$(
  curl -sS -X POST "$DIDIT_API_BASE/presentations/request" \
    -H "Authorization: Bearer $DIDIT_API_KEY" \
    -H "Content-Type: application/json" \
    --data '{
      "requested_vct": "EmployeeBadge",
      "requested_claims": ["role"],
      "aud": "office-access-rp",
      "purpose": "Confirm your role for office access"
    }'
)"

PRESENTATION_ID="$(echo "$PRESENTATION" | jq -r '.uuid')"

echo "$PRESENTATION" | jq '{
  uuid,
  dcql,
  requested_claims,
  aud,
  nonce,
  status
}'

echo "Open in the wallet: https://wallet-idv0.staging.didit.me/present?request=$PRESENTATION_ID"
```

```python Python
presentation = requests.post(
    f"{api_base}/presentations/request",
    headers=auth,
    json={
        "requested_vct": "EmployeeBadge",
        "requested_claims": ["role"],
        "aud": "office-access-rp",
        "purpose": "Confirm your role for office access",
    },
).json()
presentation_id = presentation["uuid"]

print({k: presentation.get(k) for k in (
    "uuid", "dcql", "requested_claims", "aud", "nonce", "status",
)})
print("Open in the wallet:", f"https://wallet-idv0.staging.didit.me/present?request={presentation_id}")
```
</CodeGroup>

    Open the printed wallet link in the same browser. The wallet shows the requester, the requested claim, and the disclosure choice. Approve it, and the wallet posts a key-bound `vp_token` to the public `POST /presentations/{id}/response` endpoint.

    <Frame caption="Present: the requester, the requested claims as toggles, the always-shared claims, and the claims this verifier did not ask for, then Confirm with Passkey."><img src="/images/screenshots/wallet-present-consent.png" alt="Wallet Present screen where https://veribank.example requests Given Name and Employee Id, Tier is always shared, Family Name and Department are listed as not shared, and a Confirm with Passkey button" /></Frame>

    In production, deliver the request to a wallet with the W3C Digital Credentials API using `openid4vp-v1-signed`, or render the same wallet link as a QR code. See [verify presentations](/guides/verification).
  </Step>

  <Step title="Read the verdict and the disclosed claims">
    Poll the public `GET /presentations/{id}` until it carries a `result`. That result is PII-free: it has the `verdict`, the boolean `checks`, and an `error`, but never claim values. Then read `disclosed_claims` from your backend with `GET /verifications/{id}`, which accepts the presentation request UUID and requires the tenant API key.

<CodeGroup>
```bash cURL
until curl -sS "$DIDIT_API_BASE/presentations/$PRESENTATION_ID" | jq -e '.result' >/dev/null; do
  sleep 2
done

curl -sS "$DIDIT_API_BASE/presentations/$PRESENTATION_ID" | jq '{status, result}'

curl -sS "$DIDIT_API_BASE/verifications/$PRESENTATION_ID" \
  -H "Authorization: Bearer $DIDIT_API_KEY" | jq '{
    verdict,
    disclosed_claims,
    checks
  }'
```

```python Python
import time

while True:
    status = requests.get(f"{api_base}/presentations/{presentation_id}").json()
    if "result" in status:
        break
    time.sleep(2)

print(status["result"])

verification = requests.get(
    f"{api_base}/verifications/{presentation_id}",
    headers=auth,
).json()

print({k: verification[k] for k in ("verdict", "disclosed_claims", "checks")})
```
</CodeGroup>
  </Step>
</Steps>

## Read the verification result

`GET /verifications/{id}` returns the full verification record.

<ResponseField name="verdict" type="string">
  `verified` means Didit ID accepted the presentation. Any other value is `failed`, and `error` says why.
</ResponseField>

<ResponseField name="disclosed_claims" type="object">
  The claims the holder disclosed. In this quickstart, the verifier requests only `role`, so `employee_id` and `department` stay undisclosed.
</ResponseField>

<ResponseField name="checks" type="object">
  The verification checks. A verified response includes successful checks for `signature`, `key_binding`, `aud`, `nonce`, `alg_allowlist`, `not_expired`, and `not_revoked`.
</ResponseField>

<ResponseField name="request_id" type="string">
  The presentation request UUID. `vct`, `verifier` (the request `aud`), and `requested_claims` are echoed alongside it.
</ResponseField>
