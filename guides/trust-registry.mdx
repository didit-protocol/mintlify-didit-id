Use the trust registry to decide which issuers each verifier accepts. Trust can come from a governed framework, an individual issuer, or a relying-party-specific policy. Didit ID applies that policy automatically during [OpenID4VP verification](/guides/verification).

Trust decisions are separate from cryptographic checks. At verification time, Didit ID checks the credential signature, holder key binding, audience, nonce, algorithm allowlist, expiry, revocation, and the applicable trust policy.

## Choose the account trust policy

The account trust policy is the default policy for relying parties that inherit trust from the account.

<Steps>
  <Step title="Review Didit Network">
    New accounts trust the **Didit Network** framework by default. It represents issuers on the Didit platform and keeps the live sandbox working immediately.
  </Step>
  <Step title="Trust or disable frameworks">
    Trust a whole framework when its governance is enough. Turn framework trust off when you want explicit issuer approval.
  </Step>
  <Step title="Add issuer overrides">
    Block a specific issuer inside a trusted framework when the framework is generally trusted but that issuer should not be accepted.
  </Step>
  <Step title="Add individual issuers">
    Trust individual issuers when you do not want to accept a whole framework.
  </Step>
</Steps>

List frameworks with [`GET /trust-frameworks`](/api-reference/trust/trust-frameworks-get), inspect one with [`GET /trust-frameworks/{slug}`](/api-reference/trust/trust-frameworks-slug-get), and update account framework trust with [`PUT /trust-frameworks/{slug}/trust`](/api-reference/trust/trust-frameworks-slug-trust-put).

Create per-issuer framework exceptions with [`POST /trust-frameworks/{slug}/issuer-overrides`](/api-reference/trust/trust-frameworks-slug-issuer-overrides-post).

## Add a trusted issuer

Create a trusted issuer entry with [`POST /trusted-issuers`](/api-reference/trust/trusted-issuers-post). Use this when you want to accept one issuer directly.

<ParamField body="name" type="string">
  Human-readable issuer name, such as `State University Registrar`.
</ParamField>

<ParamField body="iss" type="string">
  Issuer identifier that appears in SD-JWT VCs, such as `https://id.state-university.example`. This value is immutable after creation.
</ParamField>

<ParamField body="trust_anchor" type="string">
  Trust anchor for the issuer entry. Use a JWKS endpoint, `did:web`, or x509 material depending on the issuer ecosystem.
</ParamField>

<ParamField body="jwks_uri" type="string">
  JWKS URI for issuer signing keys when the issuer uses a JWKS trust anchor.
</ParamField>

<ParamField body="did" type="string">
  DID for issuers anchored by `did:web`.
</ParamField>

<ParamField body="framework" type="string">
  Trust framework identifier for the issuer.
</ParamField>

<CodeGroup>
  ```bash cURL
  curl -X POST https://idv0.staging.didit.me/v1/trusted-issuers \
    -H "Authorization: Bearer $DIDIT_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "name": "State University Registrar",
      "iss": "https://id.state-university.example",
      "trust_anchor": "did-web",
      "framework": "education"
    }'
  ```

  ```js JavaScript
  const response = await fetch("https://idv0.staging.didit.me/v1/trusted-issuers", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.DIDIT_API_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      name: "State University Registrar",
      iss: "https://id.state-university.example",
      trust_anchor: "did-web",
      framework: "education",
    }),
  });

  const trustedIssuer = await response.json();
  ```
</CodeGroup>

You can edit the issuer name, trust anchor, JWKS URI, DID, and framework with [`PATCH /trusted-issuers/{uuid}`](/api-reference/trust/trusted-issuers-uuid-patch). The `iss` value is the stable issuer identity and cannot be changed.

## Validate a trusted issuer

Use [`POST /trusted-issuers/{uuid}/validate`](/api-reference/trust/trusted-issuers-uuid-validate-post) after you add or edit an issuer.

Issuer validation resolves the issuer against its published SD-JWT VC issuer metadata at `/.well-known/jwt-vc-issuer` and its keys. The console shows a validation status so operators can see whether an issuer entry resolves cleanly.

<CodeGroup>
  ```bash cURL
  curl -X POST https://idv0.staging.didit.me/v1/trusted-issuers/$TRUSTED_ISSUER_ID/validate \
    -H "Authorization: Bearer $DIDIT_API_KEY"
  ```

  ```js JavaScript
  const trustedIssuerId = process.env.TRUSTED_ISSUER_ID;

  await fetch(`https://idv0.staging.didit.me/v1/trusted-issuers/${trustedIssuerId}/validate`, {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.DIDIT_API_KEY}`,
    },
  });
  ```
</CodeGroup>

<Tip>
  Validation helps you configure trust. Verification still checks the credential signature against issuer keys every time a holder presents a credential.
</Tip>

## Configure relying-party policy

A relying party is a verifier application, brand, product, or journey. Each relying party can inherit the account policy or define its own accepted frameworks and issuers.

Use per-relying-party policy when one account operates many verifiers. For example, you can onboard multiple brands or airlines as separate relying parties, then give each one its own accepted frameworks and blocked issuer exceptions.

Register relying parties with [`POST /relying-parties`](/api-reference/trust/relying-parties-post), list them with [`GET /relying-parties`](/api-reference/trust/relying-parties-get), update policy with [`PATCH /relying-parties/{uuid}`](/api-reference/trust/relying-parties-uuid-patch), and delete them with [`DELETE /relying-parties/{uuid}`](/api-reference/trust/relying-parties-uuid-delete).

## Use trust during verification

When your backend creates a presentation request, choose the relying party or audience that represents the verifier. Didit ID applies that relying party's trust policy automatically when the wallet submits the `vp_token`.

You can still pass `trusted_iss` to narrow a request to one issuer. It is an issuer filter, not a replacement for policy. The submitted credential must match `trusted_iss` and pass the applicable account or relying-party trust policy.

<CodeGroup>
  ```bash cURL
  curl -X POST https://idv0.staging.didit.me/v1/presentations/request \
    -H "Authorization: Bearer $DIDIT_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{
      "requested_vct": "StudentID",
      "requested_claims": ["program"],
      "aud": "campus-door",
      "trusted_iss": "https://id.state-university.example"
    }'
  ```

  ```js JavaScript
  const response = await fetch("https://idv0.staging.didit.me/v1/presentations/request", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.DIDIT_API_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      requested_vct: "StudentID",
      requested_claims: ["program"],
      aud: "campus-door",
      trusted_iss: "https://id.state-university.example",
    }),
  });

  const presentationRequest = await response.json();
  ```
</CodeGroup>

See [Verify presentations](/guides/verification), [Build a relying party](/guides/relying-party), and [`POST /presentations/request`](/api-reference/verification/presentations-request-post) for the full OpenID4VP flow.

## Remove trust registry entries

Remove trusted issuers and relying parties by UUID. Removal changes future trust decisions for the account or relying party.

<CodeGroup>
  ```bash cURL
  curl -X DELETE https://idv0.staging.didit.me/v1/trusted-issuers/$TRUSTED_ISSUER_ID \
    -H "Authorization: Bearer $DIDIT_API_KEY"

  curl -X DELETE https://idv0.staging.didit.me/v1/relying-parties/$RELYING_PARTY_ID \
    -H "Authorization: Bearer $DIDIT_API_KEY"
  ```

  ```js JavaScript
  await fetch(`https://idv0.staging.didit.me/v1/trusted-issuers/${process.env.TRUSTED_ISSUER_ID}`, {
    method: "DELETE",
    headers: {
      Authorization: `Bearer ${process.env.DIDIT_API_KEY}`,
    },
  });

  await fetch(`https://idv0.staging.didit.me/v1/relying-parties/${process.env.RELYING_PARTY_ID}`, {
    method: "DELETE",
    headers: {
      Authorization: `Bearer ${process.env.DIDIT_API_KEY}`,
    },
  });
  ```
</CodeGroup>

<Warning>
  Review active verification flows before you remove framework trust, issuer overrides, trusted issuers, or relying-party policy. The change affects future verification verdicts.
</Warning>
