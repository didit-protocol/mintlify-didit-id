Use the hosted wallet to claim a credential from an email link, then present it to the VeriBank relying-party demo. You need a passkey-capable browser and an email address you can read.

<Steps>
  <Step title="Issue a credential from the console">
    Open the [console](https://console-idv0.staging.didit.me), create or select a credential template, and send a credential offer to your email. Keep the transaction code if the offer requires one.
  </Step>

  <Step title="Open the claim link">
    Open the claim email and follow the wallet link. The wallet opens at [wallet-idv0.staging.didit.me](https://wallet-idv0.staging.didit.me).
  </Step>

  <Step title="Sign in with a passkey">
    Create or open your wallet account with a passkey-capable browser. The passkey protects access to your wallet and credentials.
  </Step>

  <Step title="Claim the credential">
    Review the issuer, credential type, and requested transaction code. When you approve, the wallet runs the OpenID4VCI exchange and stores the SD-JWT VC.

    <Frame caption="Add to Wallet: the issuer, the credential type, and each claim marked You choose (selectively disclosable) or Always shared. The transaction code entry and the Add to Wallet button follow below."><img src="/images/screenshots/wallet-claim-offer.png" alt="Wallet Add to Wallet screen showing an employee badge offer from skyhop-airlines with Given Name, Family Name, Employee Id and Department marked You choose and Tier marked Always shared" /></Frame>
  </Step>

  <Step title="Open VeriBank">
    Open [VeriBank](https://veribank-idv0.staging.didit.me), choose a scenario, and follow the QR or same-device link back to the wallet.
  </Step>

  <Step title="Present with selective disclosure">
    Review the relying party and requested claims. Approve the presentation. The wallet submits an OpenID4VP `vp_token` with only the approved disclosures.

    <Frame caption="Present: the requester, the requested claims as toggles, the always-shared claims, and the claims this verifier did not ask for, then Confirm with Passkey."><img src="/images/screenshots/wallet-present-consent.png" alt="Wallet Present screen where https://veribank.example requests Given Name and Employee Id, Tier is always shared, Family Name and Department are listed as not shared, and a Confirm with Passkey button" /></Frame>
  </Step>
</Steps>

## Troubleshooting

<AccordionGroup>
  <Accordion title="The passkey prompt does not appear">
    Use Chrome, Safari, or Edge on a device with a platform authenticator such as Touch ID or Windows Hello, or use a compatible security key.
  </Accordion>
  <Accordion title="The transaction code is rejected">
    The transaction code comes from the issuer. Confirm you entered the exact code for this offer. If the offer locks or expires, ask the issuer to resend it.
  </Accordion>
  <Accordion title="The offer says not found or expired">
    Offers are single-use and time-limited. Ask the issuer to send a fresh claim email.
  </Accordion>
  <Accordion title="The wallet has no matching credential">
    The wallet only presents credentials whose `vct` and claim set match the verifier request. Claim the requested credential type first, then retry.
  </Accordion>
</AccordionGroup>
